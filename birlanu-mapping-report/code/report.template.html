04Reading the numbers

How the counts are built

01
A product is a description The unit is the product title printed on the invoice, normalised for case, quote marks, unit spacing and known spelling variants. One catalogue SKU can account for several descriptions — the counts below are descriptions, not catalogue items.
02
Fully, partly, never A description is fully mapped when every line it appears on carries a SKU, partly when only some do, and never when none do. Mapping runs per distributor catalogue, so the same description can map for one distributor and not another in the same week.
03
Branding not found counts as mapped Both Mapped and Mapped — branding not found carry a SKU. The second means the product was identified but the invoice title did not carry the brand token; it is not a failure.
04
Duplicates are set aside @@DUPS@@ of @@LINES_ALL@@ lines are flagged as duplicate invoices and are excluded from every count on these pages. Products are counted only on the @@LINES@@ remaining lines.
05Scope
A
One week These are the counts for @@WINDOW@@ only. They describe this window, not a year-to-date population, and are not comparable with counts covering a longer period.
B
The export we were given It lists SKUs in the 9000, 9600, 9800 and 9900 series only. An item that exists solely under another series cannot appear as matched here; absence from this report is not evidence that a product is missing from the catalogue.
C
Mapping only This report covers identification and product mapping counts. Line value is outside its scope.

How each reason is read. Every description and party is taken from the line itself and matched against the @@CAT_SKUS@@-SKU catalogue extract of @@CAT_DATE@@: a shared product word and the title’s own size decide the group, and a brand the catalogue does not carry reads as another manufacturer’s product. Nothing is inferred about a party beyond the identifier the invoice carried.
